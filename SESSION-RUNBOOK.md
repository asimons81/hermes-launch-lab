# Session runbook

## Before the call

- Confirm payment, service, scope, client time zone, and private Google Meet details.
- Review intake without copying it into logs or unrelated tools.
- Confirm the client has a current backup or explicitly avoid material-risk changes.
- Prepare a written change log and verification checklist.

## Opening checklist

- Confirm client identity, desired outcome, authorized systems, backup state, and remaining session time.
- State that the session is not recorded.
- Offer screen-share coaching first. If attended access is useful, have the client generate a new Chrome Remote Desktop support code.
- Confirm verbally that the client authorizes access, will remain present, and can disconnect at any time.

## During work

- Never install unattended access.
- Have the client enter passwords, MFA codes, API keys, and other secrets.
- Stop sharing before unrelated sensitive information is exposed.
- Keep changes within scope and maintain a reversible change log.
- Stop when authorization is unclear, backup protection is inadequate, credentials are exposed, or the requested action is unsafe or unlawful.

## Handoff

- Test the agreed deliverable with the client.
- Explain what changed, remaining limitations, and any provider-dependent behavior.
- Disconnect remote access and have the client close the support session.
- Identify temporary access, tokens, or permissions the client should revoke or rotate.
- Send written notes, client-owned deliverables, and the exact follow-up expiration time.

## Seven-day follow-up

Use one continuing email thread for defects in the agreed Launch configuration. New features, expanded scope, provider outages, and third-party updates require new scope.
